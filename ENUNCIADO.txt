PROBLEMA DEL EQUIPO 2: COTIZACIÓN DE ENVÍOS

Una oficina de mensajería necesita administrar solicitudes de envío local e interurbano. Cada registro representa una solicitud con código, destino y peso. La aplicación debe permitir cargar las solicitudes, agregar otras, consultar sus datos, eliminar solicitudes canceladas y calcular el costo de la solicitud seleccionada. No se requiere seguimiento de paquetes ni integración con mapas.

JERARQUÍA ENTREGADA
Envio: codigo (String), destino (String), pesoKg (double).
EnvioLocal hereda de Envio y agrega tarifaPorKg (double).
EnvioInterurbano hereda de Envio y agrega distanciaKm (double).

OPERACIÓN PRINCIPAL
Contrato a completar: double calcularImporte().
El usuario selecciona un envío. El cálculo utiliza los datos almacenados en el objeto y no requiere una cantidad adicional.
EnvioLocal: Importe base = 2000 + pesoKg × tarifaPorKg.
EnvioInterurbano: Importe base = 5000 + pesoKg × 1500 + distanciaKm × 20.
Modalidad NORMAL: total = importe base. Modalidad BENEFICIO: descuento = importe base × 0,10; total = importe base − descuento.

VALIDACIONES PARTICULARES
pesoKg debe estar entre 0,1 y 50, ambos incluidos; tarifaPorKg debe ser mayor que 0; distanciaKm debe estar entre 1 y 2000, ambos incluidos. Se aceptan decimales.

FORMATO DEL ARCHIVO
tipo;codigo;destino;pesoKg;datoEspecifico
La quinta columna (datoEspecifico) se interpreta según el tipo:
LOCAL: tarifaPorKg (double).
INTERURBANO: distanciaKm (double).
Ejemplo real del archivo:
LOCAL;EL01;Valparaíso;2.5;1800

RESULTADOS PARA COMPROBAR
Código | Entrada | Importe NORMAL | Total BENEFICIO
EL01 | Datos del registro | 6500 | 5850
ER01 | Datos del registro | 11900 | 10710
Los importes están expresados en pesos. Mostrar dos decimales.

Copiar src/equipo2/modelo en la carpeta de fuentes del proyecto, conservando el paquete equipo2.modelo.
Copiar la carpeta datos en la raíz del proyecto y ejecutar con esa raíz como directorio de trabajo.
La base contiene solo el modelo de datos. No incluye main, interfaz gráfica ni aplicación ejecutable.
Comprobación opcional de las clases base desde la carpeta del equipo, con un JDK instalado:
javac -encoding UTF-8 -d build src/equipo2/modelo/*.java
El equipo puede utilizar NetBeans, IntelliJ IDEA o Visual Studio Code con soporte para Java.

ARCHIVO Y VALIDACIONES
El archivo tiene exactamente 10 líneas iniciales, sin cabecera: 5 registros por tipo.
Cada línea tiene 5 campos separados por punto y coma (;), codificados en UTF-8.
Los números se guardan sin separador de miles, con punto para decimales.
No se permiten campos vacíos, punto y coma ni saltos de línea dentro de un campo.
El código es único al quitar espacios extremos y comparar sin distinguir mayúsculas.
El archivo puede contener otra cantidad de registros después de agregar o eliminar.
Si una línea es inválida o tiene código repetido, informar su número y continuar con
las válidas; ante duplicados conservar el primer registro válido. Ignorar líneas vacías.
Si falta el archivo, avisar y permitir trabajar con una colección vacía. Un error de
lectura/escritura debe informarse sin cerrar la aplicación ni anunciar un guardado exitoso.
Rechazar valores fuera de rango, texto en campos numéricos y valores no finitos.
El tipo desconocido y el número incorrecto de campos son errores de formato.
La modalidad y las cantidades temporales del cálculo no se guardan en el catálogo.
Todas las reglas y tarifas son didácticas. Mostrar dinero con dos decimales y no
redondear los pasos intermedios. No se agregan impuestos ni cargos no indicados.
